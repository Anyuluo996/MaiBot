## 架构概述

MaiBot 插件采用 **Host / Runner 进程隔离 + RPC** 架构：

```
┌─────────────────────────────────────────┐
│  Host（主进程）                          │
│  ├─ PluginRuntimeManager                │
│  │   ├─ BuiltinSupervisor               │
│  │   └─ ThirdPartySupervisor            │
│  ├─ ComponentRegistry（组件注册表）       │
│  ├─ EventDispatcher（事件分发）           │
│  ├─ HookCenter（命名 Hook 中心）          │
│  └─ CapabilityRegistry（能力实现）        │
│         ↑ IPC（UDS / TCP / Named Pipe）  │
│  ┌──────┴──────────────────────────┐    │
│  │ Runner（子进程，可能多个）         │    │
│  │  ├─ PluginLoader（发现+依赖+加载）│    │
│  │  ├─ Plugin A   Plugin B   ...    │    │
│  │  └─ PluginContext（能力代理）      │    │
│  └──────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

- **Host**：主进程，管理插件生命周期、组件注册、事件分发、能力实现。
- **Runner**：Host spawn 的子进程，加载并执行插件代码。一个 Host 可管理多个 Runner。
- **通信**：双方通过 msgpack 编码的 RPC 协议通信，支持 Unix Domain Socket、TCP、Named Pipe 三种传输。
- **隔离**：插件崩溃不影响主进程；插件间默认隔离，通过 API 组件显式通信。

加载流程：

```
PluginRuntimeManager.start()
  → 扫描插件目录
  → 依赖解析（拓扑排序）
  → spawn Runner 子进程
  → Runner 加载 plugin.py
  → 调用 create_plugin()
  → 注入 PluginContext
  → 注册组件到 Host
  → 调用 on_load()
```

源码位置：

- Host 端管理器：`src/plugin_runtime/integration.py`（`PluginRuntimeManager`）
- Supervisor（spawn Runner）：`src/plugin_runtime/host/supervisor.py`
- Runner 主循环：`src/plugin_runtime/runner/runner_main.py`
- 插件加载器：`src/plugin_runtime/runner/plugin_loader.py`
- 事件分发：`src/plugin_runtime/host/event_dispatcher.py`
- 能力注册：`src/plugin_runtime/capabilities/registry.py`

## 环境准备

1. 安装 SDK：

   ```bash
   pip install maibot-plugin-sdk
   ```

   MaiBot 主程序的 `pyproject.toml` 已声明依赖 `maibot-plugin-sdk>=2.7.1`。

2. 在仓库的 `plugins/` 目录下创建插件子目录。插件开发文档建议每个插件作为独立 git 仓库管理，不要修改根目录 `.gitignore`。

3. SDK 源码和详细 API 参考：
   - SDK 仓库：https://github.com/Mai-with-u/maibot-plugin-sdk
   - SDK 开发文档：https://github.com/Mai-with-u/maibot-plugin-sdk/blob/main/docs/guide.md
   - 插件市场贡献指南：https://github.com/Mai-with-u/plugin-repo/blob/main/CONTRIBUTING.md

## 最小插件结构

```
plugins/my-plugin/
├── _manifest.json     # 必填，插件元信息
├── plugin.py          # 必填，入口模块
├── config.toml        # 可选，运行时自动生成，不要提交到 git
├── .gitignore         # 建议，至少包含 /config.toml
├── README.md          # 建议
├── i18n/              # 可选，多语言资源
│   └── zh-CN.json
└── assets/            # 可选，静态资源
```

三个必填要素：

1. `_manifest.json`：声明插件 ID、版本、依赖、能力需求。
2. `plugin.py`：必须导出顶层 `create_plugin()` 工厂函数，返回插件实例。
3. 插件类继承 `MaiBotPlugin`，必须实现 `on_load()`、`on_unload()`、`on_config_update()` 三个生命周期方法。缺失任何一个，Runner 会拒绝加载。

## Manifest 清单

`_manifest.json` 是 Host 加载前的强校验依据。校验器采用 Pydantic 严格模式，禁止多余字段。

### 完整示例

```json
{
  "manifest_version": 2,
  "id": "com.example.my-plugin",
  "version": "1.0.0",
  "name": "我的插件",
  "description": "一个示例插件",
  "author": {
    "name": "开发者",
    "url": "https://github.com/developer"
  },
  "license": "MIT",
  "urls": {
    "repository": "https://github.com/developer/my-plugin",
    "homepage": "https://example.com",
    "documentation": "https://docs.example.com",
    "issues": "https://github.com/developer/my-plugin/issues"
  },
  "host_application": {
    "min_version": "1.0.0",
    "max_version": "1.99.99"
  },
  "sdk": {
    "min_version": "2.5.1",
    "max_version": "2.99.99"
  },
  "dependencies": [],
  "plugin_type": "tool",
  "display": {
    "icon": {
      "type": "lucide",
      "value": "wrench"
    }
  },
  "capabilities": ["send_message"],
  "i18n": {
    "default_locale": "zh-CN",
    "locales_path": "i18n",
    "supported_locales": ["zh-CN", "en-US"]
  }
}
```

### 必填字段

| 字段 | 说明 |
|---|---|
| `manifest_version` | 固定为 `2` |
| `id` | 唯一标识符，格式 `^[a-z0-9]+(?:[.-][a-z0-9]+)+$`，如 `com.author.plugin` |
| `version` | 严格三段式语义版本 `X.Y.Z` |
| `name` | 展示名称 |
| `description` | 描述 |
| `author` | 对象，含 `name` 和 `url`（必须 HTTP/HTTPS） |
| `license` | 许可证 |
| `urls` | 链接集合，`repository` 必填 |
| `host_application` | Host 兼容区间，含 `min_version` 和 `max_version` |
| `sdk` | SDK 兼容区间 |
| `capabilities` | 能力请求列表，不允许空值 |
| `i18n` | 国际化配置，`default_locale` 必填 |

### 可选字段

**`plugin_type`** 插件类型，影响 WebUI 展示和默认图标。可选值：`adapter`、`tool`、`provider`、`management`、`data`、`media`、`game`、`integration`、`extension`、`other`。缺省按 `extension` 处理。

**`display.icon`** WebUI 图标：

```json
{
  "display": {
    "icon": {
      "type": "lucide",
      "value": "wrench",
      "fallback": "package",
      "background": "#1f2937"
    }
  }
}
```

- `type`：`lucide`（图标名）、`emoji`（表情）、`local`（插件目录内相对路径）
- `value`：图标值
- `fallback`：加载失败时的 lucide 图标名
- `background`：背景色 `#RRGGBB`

本地图标仅支持 `.png`、`.jpg`、`.jpeg`、`.webp`、`.svg`，路径必须位于插件目录内。不允许使用在线 URL。

**`llm_providers`** LLM Provider 声明，与 `@LLMProvider` 装饰器双重声明，`client_type` 必须完全一致。两个插件声明相同 `client_type` 时，两个都被禁止加载。

### 依赖声明

`dependencies` 数组支持两种类型：

```json
[
  {
    "type": "plugin",
    "id": "com.example.other-plugin",
    "version_spec": ">=1.0.0,<2.0.0"
  },
  {
    "type": "python_package",
    "name": "httpx",
    "version_spec": ">=0.24.0"
  }
]
```

依赖解析规则：

- 插件级依赖参与拓扑排序，被依赖插件先加载；卸载时按反向顺序卸载。
- Python 包依赖会与主程序 `pyproject.toml` 约束做冲突检测，无交集则阻止加载。
- 不允许循环依赖或自依赖，不允许重复声明。

### 校验规则

- 禁止多余字段
- ID 格式：`^[a-z0-9]+(?:[.-][a-z0-9]+)+$`
- 版本号：严格 `X.Y.Z`
- URL：必须以 `http://` 或 `https://` 开头
- 不允许自依赖、重复依赖

## 生命周期

每个插件必须实现三个生命周期方法，否则 Runner 拒绝加载。

### 加载时序

```
Runner 导入 plugin.py
  → 调用 create_plugin() 获取实例
  → 注入 PluginContext（此时 self.ctx 可用）
  → 完成 capability bootstrap
  → 注册组件到 Host
  → 调用 on_load()
```

`on_load()` 在 `PluginContext` 注入和能力 bootstrap **之后**调用，可以在其中直接使用 `self.ctx` 的所有能力代理。

### create_plugin()

```python
from maibot_sdk import MaiBotPlugin

class MyPlugin(MaiBotPlugin):
    async def on_load(self) -> None: ...
    async def on_unload(self) -> None: ...
    async def on_config_update(self, scope: str, config_data: dict, version: str) -> None: ...

def create_plugin():
    return MyPlugin()
```

### on_load()

插件加载完成后的回调。典型用途：

- 初始化插件内部状态
- 注册动态 API：`self.register_dynamic_api()` + `await self.sync_dynamic_apis()`
- 上报消息网关状态：`self.ctx.gateway.update_state()`
- 读取配置并初始化资源

```python
async def on_load(self) -> None:
    self.ctx.logger.info("插件已加载，当前问候语: %s", self.config.plugin.greeting)
    self.register_dynamic_api("my_api", self._handle_api, description="示例 API", public=True)
    await self.sync_dynamic_apis()
```

### on_unload()

插件卸载前的回调。释放所有资源：关闭连接、文件句柄、后台任务，上报网关离线，注销动态 API。

```python
async def on_unload(self) -> None:
    self.ctx.logger.info("插件正在卸载")
    await self.ctx.gateway.update_state(gateway_name="my_gateway", ready=False)
    self.clear_dynamic_apis()
    await self.sync_dynamic_apis(offline_reason="插件已卸载")
```

`on_unload()` 中仍可使用 `self.ctx`，但应尽快完成清理，不执行耗时操作。

### on_config_update()

配置热重载回调。

```python
async def on_config_update(self, scope: str, config_data: dict, version: str) -> None:
    ...
```

`scope` 取值：

| scope | 含义 | 触发条件 |
|---|---|---|
| `"self"` | 插件自身配置 | `config.toml` 变化时**始终触发**，无需订阅 |
| `"bot"` | 全局 Bot 配置 | 需通过 `config_reload_subscriptions` 订阅 |
| `"model"` | LLM 模型配置 | 需通过 `config_reload_subscriptions` 订阅 |

订阅全局配置：

```python
from typing import ClassVar, Iterable
from maibot_sdk import CONFIG_RELOAD_SCOPE_SELF, ON_BOT_CONFIG_RELOAD, ON_MODEL_CONFIG_RELOAD

class MyPlugin(MaiBotPlugin):
    config_reload_subscriptions: ClassVar[Iterable[str]] = ("bot", "model")

    async def on_config_update(self, scope: str, config_data: dict, version: str) -> None:
        if scope == CONFIG_RELOAD_SCOPE_SELF:
            # self.config 已自动更新
            ...
        elif scope == ON_BOT_CONFIG_RELOAD:
            bot_name = config_data.get("bot_name", "未知")
            ...
        elif scope == ON_MODEL_CONFIG_RELOAD:
            ...
```

规则：

- 默认值为空元组 `()`，不订阅任何全局配置
- `"self"` 始终触发，不需要也不能在此声明
- 仅 `"bot"` 和 `"model"` 是有效订阅值
- 必须使用可迭代集合，不能传字符串

## 配置管理

插件通过 `PluginConfigBase` + `Field` 声明强类型配置模型。Runner 根据 `config_model` 生成默认配置、补齐缺失字段，并向 WebUI 暴露可渲染的 Schema。

### 基本用法

```python
from maibot_sdk import MaiBotPlugin, PluginConfigBase, Field

class MyPluginConfig(PluginConfigBase):
    __ui_label__ = "插件配置"

    enabled: bool = Field(default=True, description="是否启用插件")
    greeting: str = Field(default="你好！", description="默认问候语")
    max_retries: int = Field(default=3, description="最大重试次数")

class MyPlugin(MaiBotPlugin):
    config_model = MyPluginConfig

    async def on_load(self) -> None:
        self.ctx.logger.info("当前问候语: %s", self.config.greeting)
        self.ctx.logger.info("最大重试: %d", self.config.max_retries)
```

### 嵌套配置

通过嵌套 `PluginConfigBase` 实现分组：

```python
class PluginSection(PluginConfigBase):
    __ui_label__ = "基础设置"
    __ui_icon__ = "settings"
    __ui_order__ = 0

    enabled: bool = Field(default=True, description="是否启用插件")
    greeting: str = Field(default="你好！", description="默认问候语")

class AdvancedSection(PluginConfigBase):
    __ui_label__ = "高级设置"
    __ui_icon__ = "tune"
    __ui_order__ = 1

    max_retries: int = Field(default=3, description="最大重试次数")
    timeout: float = Field(default=30.0, description="超时时间（秒）")

class MyPluginConfig(PluginConfigBase):
    plugin: PluginSection = Field(default_factory=PluginSection)
    advanced: AdvancedSection = Field(default_factory=AdvancedSection)
```

### Field 字段

```python
Field(
    default=...,            # 默认值
    default_factory=...,     # 可变默认值的工厂函数
    description="...",       # WebUI 中显示的标签
    json_schema_extra={      # 额外元数据
        "placeholder": "请输入...",
        "group": "basic",
    },
)
```

WebUI 展示元数据（类属性）：

- `__ui_label__`：分组标题
- `__ui_icon__`：Material Icons 图标名
- `__ui_order__`：排序权重，数值越小越靠前

### 访问配置

强类型访问（推荐）：

```python
greeting = self.config.plugin.greeting
timeout = self.config.advanced.timeout
```

未声明 `config_model` 时调用 `self.config` 会抛 `RuntimeError`。

原始字典访问（始终可用，无需声明 `config_model`）：

```python
raw = self.get_plugin_config_data()
greeting = raw.get("plugin", {}).get("greeting", "默认值")
```

### 配置热重载

`config.toml` 变化时 Runner 自动触发 `on_config_update(scope="self")`，`self.config` 在回调时已自动更新，无需手动重新读取。

### config.toml 格式

```toml
[plugin]
config_version = "1.0.0"
enabled = true
greeting = "你好！"

[advanced]
max_retries = 3
timeout = 30.0
```

`config_version` 是特殊字段，用于跟踪配置版本。Runner 合并默认配置时保留此字段。

插件源码仓库的 `.gitignore` 应包含 `/config.toml`，运行时配置由 Runner 根据 `config_model` 生成和维护。

### 通过能力代理读取

```python
value = await self.ctx.config.get("plugin.greeting")           # 读自身配置
other = await self.ctx.config.get_plugin("com.other.plugin")   # 读其他插件配置
all_config = await self.ctx.config.get_all()                   # 读全局 Bot 配置
```

## 组件开发

插件通过装饰器声明组件。SDK 提供八个装饰器：

| 装饰器 | 用途 |
|---|---|
| `@Tool` | LLM 可调用的工具，最常用 |
| `@Command` | 正则匹配的用户命令 |
| `@HookHandler` | 订阅命名 Hook 点，可拦截/改写主流程 |
| `@EventHandler` | 订阅固定事件类型 |
| `@API` | 插件间通信接口 |
| `@MessageGateway` | 接入外部聊天平台 |
| `@LLMProvider` | 声明新的 LLM Provider |
| `@Action` | 旧版装饰器，SDK 内部自动转换为 `@Tool`，新插件不要使用 |

### 组件选择决策

- 让 LLM 主动调用能力 → `@Tool`
- 用户输入命令触发 → `@Command`
- 拦截或观察主流程（消息改写、发送审计） → `@HookHandler`
- 监听消息或生命周期事件（统计、记录） → `@EventHandler`
- 给其他插件调用能力 → `@API`
- 接入外部聊天平台 → `@MessageGateway`

---

### Tool：让 LLM 调用你的能力

`@Tool` 是最核心的组件类型。LLM 在推理过程中可以主动调用 Tool 获取外部信息或执行操作。

#### 装饰器签名

```python
from maibot_sdk import Tool
from maibot_sdk.types import ToolParameterInfo, ToolParamType

@Tool(
    name: str,                                  # 工具名称（必填，插件内唯一）
    description: str = "",                      # 备选描述
    brief_description: str = "",                # 简要描述（优先使用）
    detailed_description: str = "",             # 详细描述
    parameters: list[ToolParameterInfo] | dict | None = None,
    **metadata,                                 # 如 core_tool=True
)
```

描述字段优先级：`brief_description` > `description` > 自动生成 `"工具 {name}"`。`detailed_description` 会与参数 Schema 合并生成完整描述。

#### 参数定义

推荐用 `ToolParameterInfo` 结构化声明：

```python
@Tool(
    "search",
    brief_description="搜索互联网获取信息",
    detailed_description="使用搜索引擎查找相关信息。\n- query：string，必填。搜索关键词。\n- limit：integer，可选。返回结果数量上限。",
    parameters=[
        ToolParameterInfo(
            name="query",
            param_type=ToolParamType.STRING,
            description="搜索关键词",
            required=True,
        ),
        ToolParameterInfo(
            name="limit",
            param_type=ToolParamType.INTEGER,
            description="返回结果数量上限",
            required=False,
            default=5,
        ),
    ],
)
async def handle_search(self, query: str, limit: int = 5, **kwargs):
    results = await self._do_search(query, limit)
    return {"results": results}
```

`ToolParamType` 枚举：`STRING`、`INTEGER`、`NUMBER`、`FLOAT`、`BOOLEAN`、`ARRAY`、`OBJECT`。

`ToolParameterInfo` 字段：

| 字段 | 说明 |
|---|---|
| `name` | 参数名 |
| `param_type` | 类型枚举 |
| `description` | 描述 |
| `required` | 是否必填，默认 `True` |
| `enum_values` | 枚举值列表 |
| `default` | 默认值 |
| `items_schema` | 数组元素 Schema（`ARRAY` 时） |
| `properties` | 对象属性（`OBJECT` 时） |
| `required_properties` | 对象必填字段 |
| `additional_properties` | 是否允许额外字段 |

#### 返回值

返回 `dict`（推荐）、`str` 或其他可序列化值。LLM 根据返回值决定下一步。

#### 返回图片和媒体

不要把 base64 塞进 `content` 长文本。返回 `dict`，文字放 `content`，媒体放 `content_items`：

```python
from base64 import b64encode

async def handle_draw(self, prompt: str, **kwargs):
    image_bytes = await self._draw_image(prompt)
    return {
        "success": True,
        "content": "图片已生成，请查看索引对应的图片内容。",
        "content_items": [
            {
                "type": "image",
                "data": b64encode(image_bytes).decode("ascii"),
                "mime_type": "image/png",
                "name": "result.png",
                "description": "根据提示词生成的图片",
            }
        ],
    }
```

Maisaka 会把这种返回拆成两条上下文消息：第一条是纯文本 Tool Result（含媒体索引），第二条是带真实图片组件的 user message。这样兼容不支持在 tool result 中回传图片的模型 API。

#### kwargs 中的额外参数

- `stream_id`：当前聊天流 ID，用于 `ctx.send.text()`
- `message`：触发此工具调用的原始消息 dict

#### core_tool

默认工具进入 deferred 池，需要被 LLM 搜索发现后才调用。高频低风险工具可设 `core_tool=True` 直接进入核心工具池，但过多核心工具会增加模型选择成本，默认不要设置。

### Command：正则命令

用户消息匹配正则 `pattern` 时触发。

#### 装饰器签名

```python
from maibot_sdk import Command

@Command(
    name: str,                        # 命令名称（必填，插件内唯一）
    description: str = "",
    pattern: str = "",                # 正则匹配模式
    aliases: list[str] | None = None, # 别名列表
)
```

#### 基本用法

```python
@Command("hello", pattern=r"^/hello$")
async def handle_hello(self, **kwargs):
    await self.ctx.send.text("Hello!", kwargs["stream_id"])
    return True, "Hello!", 2
```

带别名：

```python
@Command("greet", pattern=r"^/greet$", aliases=["/hi", "/hey"])
async def handle_greet(self, **kwargs):
    ...
```

带命名捕获组：

```python
@Command("echo", pattern=r"^/echo\s+(?P<text>.+)$")
async def handle_echo(self, **kwargs):
    matched = kwargs.get("matched_groups", {})
    text = matched.get("text", "").strip()
    await self.ctx.send.text(f"Echo: {text}", kwargs["stream_id"])
    return True, f"Echo: {text}", 1
```

#### kwargs 内容

| 参数 | 说明 |
|---|---|
| `stream_id` | 当前聊天流 ID |
| `matched_groups` | 命名捕获组匹配结果 dict |
| `raw_message` | 用户原始消息文本 |
| `message` | 完整消息对象 |

#### 返回值

必须返回三元组 `(success, response, weight)`：

- `success`：bool，是否成功
- `response`：str，结果描述
- `weight`：int，优先级权重，越高越优先

#### 正则模式推荐

```python
r"^/hello$"                          # 精确匹配
r"^/hello(?P<name>.+)?$"             # 可选参数
r"^/echo\s+(?P<text>.+)$"            # 必填参数
r"^/set\s+(?P<key>\w+)\s+(?P<value>.+)$"  # 多参数
```

命令执行前后有内置 Hook：`chat.command.before_execute`、`chat.command.after_execute`。

### HookHandler：订阅命名 Hook 点

`@HookHandler` 订阅主程序在关键执行点触发的命名 Hook。与 `@EventHandler` 的区别：HookHandler 基于字符串 Hook 名（可无限扩展），EventHandler 基于固定 `EventType` 枚举。

#### 装饰器签名

```python
from maibot_sdk import HookHandler
from maibot_sdk.types import HookMode, HookOrder, ErrorPolicy

@HookHandler(
    hook: str,                                 # 命名 Hook 名称（必填）
    name: str = "",                            # 组件名称
    description: str = "",
    mode: HookMode = HookMode.BLOCKING,        # 处理模式
    order: HookOrder = HookOrder.NORMAL,       # 顺序槽位
    timeout_ms: int = 0,                       # 超时，0 = 使用默认
    error_policy: ErrorPolicy = ErrorPolicy.SKIP,
)
```

#### 处理模式

**`BLOCKING`（阻塞）**：串行执行，可修改传入的 `kwargs`。返回 `modified_kwargs` 可更新后续处理器参数，返回 `action: "abort"` 可终止整个 Hook 调用链。适合消息拦截、改写。

**`OBSERVE`（观察）**：后台并发执行，只读旁路。返回值被忽略。适合日志记录、数据分析。

#### 顺序槽位

同一模式内按 `order` 排序：

- `HookOrder.EARLY`：优先执行，适合前置拦截
- `HookOrder.NORMAL`：默认
- `HookOrder.LATE`：延后执行，适合补充处理

#### 异常处理策略

- `ErrorPolicy.ABORT`：异常时终止当前 Hook 调用
- `ErrorPolicy.SKIP`（默认）：记录日志，跳过此处理器继续
- `ErrorPolicy.LOG`：记录日志并继续

#### 调度顺序

1. 模式优先：blocking 先于 observe
2. 顺序槽位：early → normal → late
3. 来源优先：内置插件先于第三方
4. 插件 ID：字典序
5. 处理器名称：字典序

#### 示例：拦截并修改消息

```python
@HookHandler(
    "chat.receive.before_process",
    name="message_filter",
    mode=HookMode.BLOCKING,
    order=HookOrder.EARLY,
    error_policy=ErrorPolicy.ABORT,
)
async def handle_message_filter(self, **kwargs):
    message = kwargs.get("message", {})
    raw_message = message.get("raw_message", "")
    if "违禁词" in raw_message:
        return {"action": "abort"}

    kwargs["message"]["filtered"] = True
    return {"action": "continue", "modified_kwargs": kwargs}
```

#### 示例：观察模式记录日志

```python
@HookHandler(
    "chat.receive.after_process",
    name="message_logger",
    mode=HookMode.OBSERVE,
    order=HookOrder.LATE,
)
async def observe_message(self, **kwargs):
    message = kwargs.get("message", {})
    self.ctx.logger.info("观察到消息: %s", message.get("raw_message", ""))
```

#### 处理器返回值

阻塞模式返回 dict：

- `action`：`"continue"` 或 `"abort"`
- `modified_kwargs`：修改后的参数

观察模式返回值被忽略。

**⚠️ `modified_kwargs` 是整体替换，不是按键合并**：宿主把它整个替换进本次分发的参数，
再传给排在后面的订阅者。因此：

1. 返回 `modified_kwargs` 时必须带回全部原始键——包括 `**kwargs` 展开，以及被函数
   签名具名参数吸收的键。具名参数（如 `items`、`session_id`）不会进入 `**kwargs`，
   `dict(kwargs)` 也带不回它们：

   ```python
   # ✅ 正确：显式放回具名参数，其余从 **kwargs 继承
   modified = {"items": items, "session_id": session_id, **kwargs}

   # ❌ 错误：空 dict 起步丢失全部键
   modified = {}
   # ❌ 错误：漏掉具名参数吸收的 items / session_id
   modified = dict(kwargs)
   ```

2. 不修改参数时返回 `{"action": "continue"}`（不带 `modified_kwargs`），对链条无影响。

缺键的代价是隐蔽的：排在后面的钩子（往往是其他插件的）拿到缺键载荷后静默失效，
零日志零报错。历史上 prompt-guard（2026-10-21）与 ov-memory（2026-10-27）两次
真实事故均为这两种错误模式。

#### Host 校验规则

注册阶段校验，不合法直接注册失败：

1. Hook 名称必须已在 Host 注册
2. mode 必须与 Hook 能力约束兼容
3. `error_policy=ABORT` 要求 Hook 允许 abort

### EventHandler：订阅事件

`@EventHandler` 基于固定 `EventType` 枚举订阅事件。

#### 装饰器签名

```python
from maibot_sdk import EventHandler
from maibot_sdk.types import EventType

@EventHandler(
    name: str,                                  # 组件名称（必填）
    description: str = "",
    event_type: EventType = EventType.ON_MESSAGE,
    intercept_message: bool = False,            # 是否阻塞消息链
    weight: int = 0,                            # 越高越先执行
)
```

#### EventType 枚举

| 类型 | 触发时机 |
|---|---|
| `ON_START` | 插件启动 |
| `ON_STOP` | 插件停止 |
| `ON_MESSAGE_PRE_PROCESS` | 消息预处理阶段（过滤、拦截最佳时机） |
| `ON_MESSAGE` | 消息处理阶段 |
| `ON_PLAN` | 规划阶段 |
| `POST_LLM` | LLM 调用后（响应已生成） |
| `AFTER_LLM` | LLM 调用完成后 |
| `POST_SEND_PRE_PROCESS` | 发送预处理阶段 |
| `POST_SEND` | 消息发送后 |
| `AFTER_SEND` | 消息发送完成后 |

#### intercept_message

- `False`（默认）：异步 fire-and-forget，不影响主流程
- `True`：同步阻塞，可拦截、修改、阻止后续处理

#### 示例：消息过滤

```python
@EventHandler(
    "spam_filter",
    event_type=EventType.ON_MESSAGE_PRE_PROCESS,
    intercept_message=True,
    weight=100,
)
async def filter_spam(self, message, **kwargs):
    raw_message = message.get("raw_message", "")
    if self._is_spam(raw_message):
        return {"intercepted": True, "reason": "spam"}
    return {"intercepted": False}
```

#### 与 HookHandler 的区别

| 维度 | EventHandler | HookHandler |
|---|---|---|
| 订阅方式 | `EventType` 枚举 | 字符串 Hook 名 |
| 粒度 | 固定事件类型，数量有限 | 自定义 Hook 名，可扩展 |
| 拦截方式 | `intercept_message=True` | `mode=HookMode.BLOCKING` |
| 优先级 | `weight` 数值 | `order` 三档枚举 + 全局排序 |
| 异常策略 | 无专用参数 | `error_policy` |
| 适用场景 | 消息流程固定阶段 | 主程序任意扩展点 |

### API：插件间通信

`@API` 声明插件间通信接口，其他插件通过 `ctx.api.call()` 调用。

#### 装饰器签名

```python
from maibot_sdk import API

@API(
    name: str,                  # API 名称（必填，插件内唯一）
    description: str = "",
    version: str = "1",
    public: bool = False,       # 是否允许其他插件调用
)
```

#### 静态声明

```python
@API("render_html", description="将 HTML 渲染为图片", version="1", public=True)
async def handle_render_html(self, html: str, **kwargs):
    result = await self.ctx.render.html2png(html)
    return {"success": True, "image_path": result}
```

#### 动态注册

根据配置或运行时条件决定是否暴露 API：

```python
async def on_load(self) -> None:
    if self.config.enable_translate:
        self.register_dynamic_api(
            "translate",
            self._handle_translate,
            description="文本翻译",
            version="1",
            public=True,
        )
    await self.sync_dynamic_apis()

async def on_unload(self) -> None:
    self.clear_dynamic_apis()
    await self.sync_dynamic_apis(offline_reason="插件已卸载")
```

动态 API 方法：

- `self.register_dynamic_api(name, handler, *, description, version, public, handler_name)`
- `self.unregister_dynamic_api(name, *, version="1")`
- `self.clear_dynamic_apis()`
- `await self.sync_dynamic_apis(*, offline_reason="...")`

#### 调用其他插件的 API

```python
result = await self.ctx.api.call(
    "com.example.translate.translate",   # 插件 ID + API 名称
    text="你好",
    target_lang="en",
)

# 查询 API 信息
api_info = await self.ctx.api.get("com.example.translate.translate")

# 列出所有可用 API
apis = await self.ctx.api.list()
```

#### 命名规范

- 小写字母和下划线：`render_html`、`get_stats`
- 动词开头：`get_`、`render_`、`detect_`、`translate_`
- 避免过于通用的名称

## 内置 Hook 清单

Host 运行时注册的全部 Hook 点。每个 Hook 注明是否允许 abort 和是否允许改参。

### 聊天消息链

| Hook | 触发时机 | 允许 abort | 允许改参 |
|---|---|---|---|
| `chat.receive.before_process` | 入站消息执行 `process()` 前 | 是 | 是 |
| `chat.receive.after_process` | 入站消息轻量预处理完成后 | 是 | 是 |

### 命令执行链

| Hook | 触发时机 | 允许 abort | 允许改参 |
|---|---|---|---|
| `chat.command.before_execute` | 命令执行前 | 是 | 是 |
| `chat.command.after_execute` | 命令执行后 | 否 | 是 |

| Hook | 触发时机 | 允许 abort | 允许改参 |
|---|---|---|---|
| `maisaka.replyer.before_request` | replyer 请求模型前 | 否 | 是 |

`maisaka.replyer.before_model_request` 可改写实际发给模型的消息列表，适合临时提示词实验。只改写本次请求，不回写聊天历史。

## 完整示例

一个包含配置、Tool、Command、HookHandler 的完整插件：

```python
from typing import Any, ClassVar, Iterable

from maibot_sdk import (
    CONFIG_RELOAD_SCOPE_SELF,
    Command,
    Field,
    HookHandler,
    MaiBotPlugin,
    ON_BOT_CONFIG_RELOAD,
    PluginConfigBase,
    Tool,
)
from maibot_sdk.types import HookMode, HookOrder, ToolParameterInfo, ToolParamType


class PluginSection(PluginConfigBase):
    """插件基础配置。"""

    __ui_label__ = "插件"
    __ui_icon__ = "package"
    __ui_order__ = 0

    enabled: bool = Field(default=False, description="是否启用插件")
    config_version: str = Field(default="1.0.0", description="配置版本")
    default_greeting: str = Field(default="你好！", description="默认问候语")


class MyPluginConfig(PluginConfigBase):
    """插件完整配置。"""

    plugin: PluginSection = Field(default_factory=PluginSection)


class GreeterPlugin(MaiBotPlugin):
    """问候插件示例。"""

    config_model = MyPluginConfig
    config_reload_subscriptions: ClassVar[Iterable[str]] = ("bot",)

    async def on_load(self) -> None:
        self.ctx.logger.info("GreeterPlugin 已加载，问候语: %s", self.config.plugin.default_greeting)

    async def on_unload(self) -> None:
        self.ctx.logger.info("GreeterPlugin 正在卸载")

    async def on_config_update(self, scope: str, config_data: dict[str, Any], version: str) -> None:
        if scope == CONFIG_RELOAD_SCOPE_SELF:
            self.ctx.logger.info("插件配置已更新: version=%s", version)
        elif scope == ON_BOT_CONFIG_RELOAD:
            self.ctx.logger.info("Bot 配置已更新: version=%s", version)

    @Tool(
        "greet",
        brief_description="向用户打招呼",
        detailed_description="根据用户名生成问候语。\n- name：string，必填。用户名。",
        parameters=[
            ToolParameterInfo(
                name="name",
                param_type=ToolParamType.STRING,
                description="用户名",
                required=True,
            ),
        ],
    )
    async def handle_greet(self, name: str, **kwargs: Any) -> dict[str, str]:
        greeting = self.config.plugin.default_greeting
        return {"content": f"{greeting}{name}！"}

    @Command("ping", description="测试插件是否在线", pattern=r"^/ping$")
    async def handle_ping(self, stream_id: str = "", **kwargs: Any) -> tuple[bool, str, int]:
        await self.ctx.send.text("pong", stream_id)
        return True, "pong", 2

    @HookHandler(
        "chat.receive.before_process",
        name="log_inbound",
        mode=HookMode.BLOCKING,
        order=HookOrder.LATE,
    )
    async def log_inbound(self, **kwargs: Any) -> dict[str, Any]:
        message = kwargs.get("message", {})
        self.ctx.logger.debug("收到消息: %s", message.get("raw_message", ""))
        return {"action": "continue", "modified_kwargs": kwargs}


def create_plugin() -> GreeterPlugin:
    return GreeterPlugin()
```

## 测试与调试

### 静态检查

确认 `_manifest.json` 是合法 JSON，`plugin.py` 可以被 Python 解释器导入：

```bash
python -c "import json; json.load(open('_manifest.json'))"
python -c "import ast; ast.parse(open('plugin.py').read())"
```

检查 BLOCKING 钩子的 `modified_kwargs` 是否带回全部原始参数（见「处理器返回值」）：

```bash
python scripts/check_blocking_hook_kwargs.py plugins   # 全量
python scripts/check_blocking_hook_kwargs.py plugins/your_plugin   # 单个插件
```

发现问题退出码为 1。`WARN` 是 helper 封装等静态分析无法穿透的场景，需人工核对；
`ERROR` 必须修复。脚本纯标准库实现，可直接复制到服务器对生产插件目录运行。

### 本地加载

把插件放入 `plugins/` 目录，启动 MaiBot，观察插件加载日志。首次加载后 Runner 会根据 `config_model` 生成 `config.toml`。

### WebUI 检查

在 WebUI 插件管理中确认插件出现、可启用、配置可编辑。

### 命令测试

用 `/ping` 类命令确认 `@Command` 可触发。

### Tool 测试

通过正常聊天让 LLM 发现并调用工具，观察工具返回是否可读。

### 热重载

修改插件源码后，FileWatcher 会自动触发重载（debounce 600ms），无需重启 MaiBot。修改 `config.toml` 会触发 `on_config_update(scope="self")`。

### 卸载测试

禁用或卸载插件后，确认后台任务、连接和缓存被清理。

## 发布

### 仓库整理

- 插件仓库根目录包含 `_manifest.json`、`plugin.py`、`README.md`、`.gitignore`
- `.gitignore` 包含 `/config.toml`
- README 包含功能说明、安装方式、配置项、命令、权限说明、故障排查
- 许可证与 `_manifest.json` 的 `license` 一致
- 依赖声明完整，避免要求用户手动安装未声明依赖
- 没有提交 `.venv/`、`__pycache__/`、日志、数据库、密钥或本地配置

### 安装机制

MaiBot 通过 git clone 安装插件。用户在 WebUI 插件市场输入仓库地址，后端通过 `GitMirrorService.clone_repository` 克隆到 `plugins/` 目录，校验 manifest 后热加载。
