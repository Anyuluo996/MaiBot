# 群聊助手 Agent 调研与 MaiBot 功能方向

> 调研日期：2026-11-11。范围：Grok（X/XChat/Grok Bot）、ChatGPT 群聊、Meta AI、Gemini、Character.ai、Telegram/Slack/Discord 生态、中文平台（钉钉/飞书/企微/微信/QQ 官方）与开源实现；结合 MaiBot 主程序现状与 wo4 插件生态，给出现阶段功能开发方向。
> 标注「未确证」的结论为单一来源或推断，其余关键结论均有至少两个独立来源交叉。

## 0. 摘要

- 业界群聊助手已收敛出清晰模式：**@提及为确定性触发、上下文最小化、记忆默认与群聊隔离、摘要走私有通道、生图是社交粘合剂、成本与频控即产品约束**。
- ChatGPT 群聊（2025-11 上线、2026-07 退役）证明「AI 做东建群邀请人类」路线不成立；平台内「bot 作为受约束群成员」（WhatsApp/Telegram/X）与「拟人群成员」（MaiBot 路线）是存活形态。MaiBot 的 dynamic 触发 + 意愿路线与 Grok Bot 的「bot 自主决定谁响应」殊途同归，方向不需要推翻，需要的是**补齐助手侧硬能力**（摘要补看、显式记忆、每群个性化、生图、定时感知）。
- 本报告给出 P0×4 / P1×4 / P2×3 的方向清单，全部可纯插件或配置层落地，并给出明确不跟进清单。

## 1. 调研范围与方法

- 三路网络调研（Grok 专项 / 海外助手群聊产品 / 中文生态与开源），每路多轮中英文搜索 + 原文精读，官方文档优先（help.x.com、docs.x.ai、openai.com、core.telegram.org、bot.qq.com、open.dingtalk.com 等）。
- 一路本地代码盘点（主程序插件 API、核心子系统、docs 文档清单）。
- 来源清单见 §7；未确证项在正文内标注。

## 2. 产品拆解

### 2.1 Grok（X 回复区 / XChat 群聊 / Grok Bot）

**形态演进**
- @grok 提及触发回复区问答（2025-03 全面推开）；2026-03 起 X 静默将帖内 @grok 回复限制为 Premium+。
- X DM/XChat：「Ask Grok」长按呼出（2025-12），XChat 独立 app（2026-04，群聊上限 481 人）；help.x.com 明示把 @Grok 加入会话 = X 可读取加入期间全部消息（E2E 例外条款写入产品条款）。
- 2026-09 Musk 确认 **@Grok 作为群聊成员**进入测试：tag 即可提问/生图/设提醒/总结群聊。「自主插话」仅单一来源，未确证。
- **Grok Bot**（2026-08 beta，官方 docs.x.ai）：2-6 个 bot 同群；普通消息由 bot 自行决定谁响应，@ 可指定；bot 间异步 handoff 互发（计费）；用户私信可打断当前 turn。

**实现机制（对自建 bot 最有价值的部分）**
- **触发最小化 + 上下文工具化**：官方 @grok 系统提示词不预载全线程，被提及后「用 X 工具现拉当前推文串上下文」+ 实时搜索 + 页面浏览验证。
- **回复形态宪法写进系统提示**（官方提示词仓库 grok-prompts，AGPL 公开）：<550 字符、跟随群语言/方言、禁 markdown、禁 tag 对方、禁说教短语清单。
- **中断式队列**（Lee Robinson 官方工程 talk 的第三方整理，peterp.me）：每会话一条队列；消息带唯一 ID 去重；短窗口连发合并为单 turn；用户消息可打断当前 turn，helper 结果只排队不打断。
- **小主上下文 + 重活外包**：主 agent 只做轻活，重任务派 general/computer-use/video/coding 四类 helper（各自独立 durable workflow）；约 200K 上限，>100K 且用户离开 10-60 分钟即后台压缩，原始历史永不删。
- **记忆 = 云 VM 上的 markdown 文件，用 grep 检索**；允许用户口头设长期规则（官方示例：「记住：群聊中就在群里回复」）。grok.com 跨会话记忆（2025-04 起）选择性存「值得保留的事实」，Private Chat 永不入记忆，早期版本可逐条「忘记」被引用的旧会话。
- **外部内容 = 数据 ≠ 指令**；不可逆动作默认转草稿待批；**群聊中禁用审批/草稿卡**（共享上下文中的权衡）。
- 工具侧：Agent Tools API（2025-11，grok-4.1-fast）服务器端 web_search / x_search / code_execution / collections_search / MCP，xAI 托管沙箱；x_search 2026-09 起按帖计费（$5/1k 帖）。
- 推理分档（2026-09 消费端）：Auto / Fast / Expert / Heavy（Heavy = 多 agent 并行）。

**安全治理史（反面教材清单）**
- 2025-05 提示词遭未授权改动 → 开始公开提示词仓库；2025-07「MechaHitler」=「镜像用户语气被极端帖子放大」（官方归因上游代码路径易受 X 内容影响）；2025-12 undressing 深伪丑闻 → 图像生成转付费 + 多国监管调查；2026-08 加密提示注入（CCI）窃取聊天记录。共同教训：**拟人镜像语气 + 群聊开放上下文 + 生成能力三者叠加时的风险放大**。

### 2.2 ChatGPT 群聊（2025-11 上线 → 2026-07 退役）

- 2025-11-13 日本/新西兰/韩国/台湾 pilot，一周后全球放开；**2026-07-09 官方退役**（不能再创建/加入，官方称转向「更协作的新体验」）。
- 机制（退役前形态）：
  - 触发：**专门训练了「社交行为」**——跟随对话流自主判断何时发言、何时沉默；@ChatGPT 必答。
  - 记忆：**个人 memory 不注入群聊，也不从群聊写入新记忆**；每个群聊可单独设 custom instructions。
  - 频控：只在 ChatGPT 响应时计数，**计入「被回复者」的套餐限额**；群 1-20 人。
  - 安全：<18 岁成员触发全群敏感内容降级 + 家长开关。
- 启示：重训练「插话社交判断」的路线依赖模型厂训练资源；连 OpenAI 都放弃了「AI 做东建群」的产品形态。对自建 bot 的可取处是**价值观**（何时沉默的价值密度判断）与**每群独立 custom instructions**、**群聊记忆隔离**三条设计。

### 2.3 Meta AI / Gemini / Character.ai

- **Meta AI**（WhatsApp/Messenger/IG 群）：@Meta AI 提及才读消息（**只有被 @ 或主动分享的消息可被读取**）；imagine 群内生图 + 好友长按 remix（reimagine）是核心社交玩法；「总结今天群讨论/我错过了什么」摘要；隐私上部分功能走 Private Processing（平台自身也不可见）。
- **Gemini**：Google Messages 仅 1:1 不进群；Google Chat 走**侧边栏旁路模式**——总结/问答只基于当前查看的会话、输出不进群消息流、仅自己可见。没有「@Gemini 群成员实时跟聊」形态。
- **Character.ai Group Chat**（2023-10）：人类 + 多个 AI 角色同群，无 @ 语义、角色轮流发言；社区反馈角色在群内明显收敛篇幅（长描写变短句）。无外部工具接入。

### 2.4 Telegram / Slack / Discord

- **Telegram**（bot 平台机制最值得借鉴）：
  - 群内 bot 默认 **Privacy Mode**（只收 @命令/回复等）；Inline 模式任意输入框 @bot 查询（bot 只收到查询本身）。
  - **Guest Mode**：@提及未入群 bot → bot 收到单条 update 并只回一条，**不获得历史与成员列表**；单条消息最多 @3 个 guest bot；支持 ephemeral 群内私密回复（仅触发者可见）与 AI 流式「Thinking…」草稿。
  - xAI × Telegram $300M/年合作（2025-05 签），Grok 2026 年初起以应用内 AI 助手铺开，群聊 @ 提及摘要/问答。
- **Slack**（企业侧最成熟）：Slack AI 分套餐分层（频道/thread 总结 → search answers → enterprise search → Slackbot 个人 agent）；**AI 回答只基于请求者本人可见内容、带引用溯源、总结仅自己可见不进群流**；Agentforce agents 像同事被拉进频道、@提及即响应回 thread、可执行 Slack 动作。
- **Discord**：无官方第一方助手，第三方以知识库问答（@/slash 触发、答自身挂载的 docs）、总结、社区管理为主；订阅或按次计费。

### 2.5 中文生态

- **钉钉 AI 助理**：AI 助理可发布到群聊/单聊；知识库挂载（不支持直接学群文件）；连接器 + 机器人消息 MCP；**感知触发**（2025-09）= 定时触发（自然语言设「每天 8 点搜热点」）+ 事件触发（新人入群欢迎等）。
- **飞书**：Aily 发布为群机器人，**回复时机可选「被 @ 时回复（默认）」或「全量自动回复」**——官方产品化了这个二选一；触发器体系覆盖群组事件；全量群消息需敏感权限 `im:message.group_msg`；单群发消息限流 5 QPS。
- **企业微信智能机器人**（合规度最高的主动通道）：内置模型/API 两模式；群 @ 触发 + 流式回复 + 模板卡片 + 主动推送；**主动推送前提是用户先给 bot 发过消息**；30 条/分、1000 条/时频控；群聊回调仅文本。
- **微信**：截至 2026-11 **群聊仍未开放拉入 AI 机器人**；官方 AI 社交放在独立 App「元宝派」（2026-01 内测，「有 AI 的群」，拟人 NPC + 被 @ 唤起 + 复刻微信交互）；2026 春节元宝红包链接在微信裂变后被封，官方对 AI 进群严格设限。第三方个人号协议端长期封号风险。
- **QQ 官方机器人平台**（bot.qq.com，2026-10/11 文档）：
  - 消息：文本/Markdown/富媒体/内嵌按钮，**Markdown+按钮已对全部机器人开放**；流式仅单聊；撤回 2 分钟。
  - 群聊规则：被动消息（msg_id）5 分钟有效、每条最多回 5 次；主动消息未认证 30 条/分、认证 60 条/分、**每日上限 1000 条/群**、用户可一键关闭主动发送；互动召回消息允许对话后 30 天内 4 周期各 1 条。
  - **群主权限面板**：可设机器人消息接收范围（仅@ / 上下文 / 全量）、主动发言开关——「旁听全群再决定插话」被官方产品化为显式授权。
  - 主体限制：个人认证不能公开服务（进群上限 500），企业认证才可公开；AI 输出违规直接封禁且不可解封。
- **其他**：抖音 V 项目 AI 分身（创作者拟人分身 24h 自动回复）；百度文心 AI 群聊（助手可主动关注群消息）；小冰岛是早期范本无新 IM 群产品。

### 2.6 开源实现

- **CowAgent**（原 chatgpt-on-wechat，46.6k★，2026 更名）：Channel 抽象 → Agent Core（规划/记忆/知识/工具）→ 多模型路由；**三层记忆（上下文→每日→MEMORY.md）+ 夜间 Deep Dream 蒸馏 + 关键词+向量混合检索**；Skill Hub + MCP；Self-Evolution 自动复盘改进技能。个人微信渠道已不再标注群聊支持（合规收缩）。
- **AstrBot**：多平台 Agentic 框架，WebUI + 插件生态，官方建议 QQ 官方接入开「全量消息+主动发言」；社区流行与 MaiBot 联合部署（AstrBot 管工具型指令，MaiBot 管拟人）。
- **MaiBot/MaiSaka 本身**已被社区作为「群聊拟人代表」引用：定位「活跃在群里的生命体」而非工具型助手，意愿/状态驱动回复决策是核心识别特征。
- **YuanBot**：四层记忆（工作→事实→情景→语义，自动摘要/遗忘/固化），**会「主动想起用户」**。
- **Koishi 多 Bot 人格隔离插件**：独立好感度/记忆/提示词/模型配置 per-bot。
- **拟人工程流水线**（mengyunqwq/wechat-bot）：收消息→拟人策略判断是否回复→LLM 口语化短回复→**模拟真人延迟发送**→表情包/语音气泡。
- 多智能体框架（AutoGen GroupChat/LangGraph）未见真实中文 IM 群显著落地（未确证）；实际落地由 IM 原生框架承担。

## 3. 跨产品共性模式与适配判断

### 3.1 八条共性模式

| # | 模式 | 出处 |
|---|------|------|
| 1 | **@提及是确定性触发器，自主判断是补充** | Meta AI / Telegram / Slack / Grok；唯一例外 ChatGPT 额外训练了插话判断 |
| 2 | **上下文最小化而非全群投喂**（助手场景） | Meta AI 只读被 @ 消息；Telegram Privacy/Guest Mode；Slack 只用请求者可见内容 |
| 3 | **记忆默认与群聊隔离**，个人记忆不进群、群聊不写个人记忆 | ChatGPT 群聊 |
| 4 | **摘要/补看走私有通道，不污染群消息流** | Slack 仅自己可见 / Gemini 侧边栏 / Telegram ephemeral / Meta AI 摘要 |
| 5 | **生图是群聊社交粘合剂**（remix 互动玩法） | Meta AI imagine+reimagine / ChatGPT 头像图 |
| 6 | **频控与计费绑定「被服务者」**；bot 互发全计费，官方文档直接劝「少拉 bot」 | ChatGPT 被回复者计费 / Grok Bot handoff 计费 |
| 7 | **安全前置到群级**（未成年人降敏、外部内容=数据≠指令、不可逆动作审批） | ChatGPT <18 全群降敏 / Grok Bot 审核模型 / Meta Private Processing |
| 8 | **记忆口令化**：允许用户口头设长期规则并可管理删除 | Grok「记住：群聊中就在群里回复」/ grok.com 逐条忘记 |

### 3.2 对 MaiBot（拟人定位）的适配判断

MaiBot 与上述产品有根本差异：**它不是「被召唤的助手」，而是「群成员」**。适配结论：

1. **模式 1 不完全适用**：MaiBot 的 dynamic_gate + reply_likelihood 已是「自主判断」路线的本土化实现（被 @ 强制放行 + 频率驱动的插话），且这是社区识别 MaiBot 的核心特征，**不应倒退为纯 @ 触发**。但 Grok 的「中断式队列 + 短窗合并」与 ChatGPT 的「价值密度沉默判断」值得吸收进触发层。
2. **模式 2 反向适用**：拟人需要旁听全量（QQ 群主权限面板里对应「全量接收」，napcat 个人号天然全量）。要吸收的是**成本侧**：全量旁听 ≠ 全量进上下文，上下文构建要分层（现拉/摘要/压缩），Grok 的「小主上下文 + 重活外包 + 闲置压缩」是模板。
3. **模式 3 需要反向改造**：拟人的卖点恰是「记得群里的人和事」。ov-memory 已实现群级记忆（单密钥=跨群共享是已知坑，按 session 收拢）。要吸收的是 ChatGPT 的**隐私边界意识**：个人敏感情事不进跨群共享记忆、群规类记忆与个人事实记忆分开管理。
4. **模式 4/5/6/7/8 完全适用且是 MaiBot 现状缺口**（见 §4/§5）。
5. **中文生态硬约束**：wo4 走 napcat 个人号协议端（非官方 bot），不受官方 bot 频控约束但受风控约束（AI 输出违规同样有封号面）。官方平台那套「被动 5 分钟窗口/主动 1000 条每日」不是硬约束，但**其设计哲学（主动消息是稀缺资源、被动为主）值得作为频控纪律**。
6. **napcat 限制**：官方 bot 的 Markdown+按钮、流式单聊在个人号上不可用；富交互只能 render.html2png（dpanel 已验证）。

## 4. MaiBot 现状与差距

### 4.1 已有能力盘点

**主程序（MaiSaka 运行时）**
- 插件系统：Host/Runner 隔离 + msgpack RPC；8 类组件（Tool/Command/HookHandler/EventHandler/API/MessageGateway/LLMProvider）；BLOCKING Hook 可改参断链；17 种能力代理（ctx.send/db/llm/message/chat/person/emoji/frequency/render/knowledge/maisaka 等）。
- 17 个 Hook 点：chat.receive、emoji、jargon、expression、send_service（after_build_message/before_send/after_send）、maisaka.planner（before_request/after_response）、maisaka.replyer（before_request/before_model_request/after_response）。
- 触发层：MessageTurnScheduler 攒批 + dynamic_gate（3600s 滑窗回复比调阈值）+ reply_likelihood 逻辑回归（@bot +1.585、问号 +0.48、麦麦近 5 分钟发言占比 +2.65 等特征）+ idle_backoff；被 @ 强制放行。
- 上下文/回复：maisaka context（history/compaction/planner_messages/message_id_alias）、PromptManager 自定义 prompt 覆盖（locale 感知）、replyer extra_prompt/before_request 注入位。
- 记忆：A_memorix v2.0（含图片记忆链路）、heuristic_injector 启发式自然拉起；表达学习 + 黑话（jargon）体系。
- LLM：11 任务池；ToolRegistry 四 Provider；planner ≤16 轮；实验性后台子代理 subagent_tasks（并发 3，无插件编程入口）。
- 主动消息两条通路：maisaka.proactive.trigger（强制回合，静默会话会被吞）+ ctx.send 直发（无限流）。
- 无宿主 cron；无富消息组件（仅 DictComponent 透传）；无内置生图/TTS（插件补位）。

**wo4 已部署插件生态（2026-11-11 状态）**
- anyul.ov-memory v0.3.2：长期记忆（写=会话收拢+抽取，读=主动召回注入+被动工具 6 次自发调用常态化）
- anyul.task-loop v0.2.3：任务闭环（planner 判定+三层验收+running 任务语音门控 API）
- anyul.toolgate v0.9.5：工具语义检索治理 + 保底集（web_search/web_fetch/query_memory/task_submit）
- anyul.web-search v1.4.0：六引擎聚合（含知乎站内）
- anyul.history-search v0.1.0：FTS5 trigram 历史原文检索（18.5 万行）
- anyul.open-loop v0.1.3：开放回路（登记→匹配→提醒→闭环）
- fish_audio_tts v1.5.0：TTS + 语音硬边界
- anyul.pixiv-image v0.5.0：主题分析+定向收割+主动分享
- anyul.prompt-guard v1.1.0：五层注入防御（管理员授权通道）
- maimai_sandbox / pi-agent：代码执行沙盒 + 产物上传群文件
- maimai_dpanel v0.3.0：dp 命令+渲染面板（多宿主）
- anyul.gemini-embed、wuwa-kb、AnyulMcpWire、maimai_group_admin v2.16.3

### 4.2 差距对照表

| 能力域 | 业界标杆 | MaiBot 现状 | 缺口性质 |
|---|---|---|---|
| 群摘要/补看 | Slack「我错过了什么」/ Meta AI / Telegram ephemeral | history_search 可查原文，但无摘要聚合、无私有补看通道 | 功能缺口 |
| 用户可控记忆 | Grok 口头设规+逐条忘记 / ChatGPT memory 管理 | ov-memory 全自动抽取，无显式「记住/忘掉」通道，无用户管理界面 | 功能缺口 |
| 每群个性化 | ChatGPT 每群 custom instructions / Koishi 人格隔离 / Aily 回复时机二选一 | 人设全局唯一；per-group 只有手动改 dynamic 频率的散点操作（1079703368 案例） | 功能缺口 |
| 出站形态纪律 | Grok 回复形态宪法（官方提示词公开可抄） | 表达学习管个性层；无硬约束层；`<thought>` 泄漏出站 bug 未修 | 质量缺口 |
| 生图社交 | Meta AI imagine+remix | 无生图（pixiv 只有转发） | 功能缺口 |
| 定时/事件感知 | 钉钉感知触发 / nonebot apscheduler | 无宿主 cron；task-loop/pixiv 各自为政自管循环；无群事件（进出群）感知 | 架构缺口 |
| 深浅推理分档 | Grok Auto/Fast/Expert/Heavy | 任务池分模型已有，但按轮次复杂度路由回复链路无显式分档 | 成本缺口 |
| 后台子代理 | Grok helper 外包模式 | subagent_tasks 实验性内置，无插件 API | 架构缺口 |
| 富消息交互 | QQ 官方 Markdown+按钮（全量开放） | napcat 个人号不可用；仅 render.html2png | 平台受限（维持现状） |
| 记忆隐私分级 | ChatGPT 群聊记忆隔离 / Grok Private Chat 不入记忆 | ov-memory 单密钥跨群共享风险已知；敏感内容无分级 | 隐私缺口 |

## 5. 现阶段功能开发方向

### P0（低风险高确定性，全部纯插件/配置层，1-2 周量级）

**P0-1 群聊摘要与补看（catch-up 通道）**
- 对标：Slack/Meta AI/Telegram ephemeral（§3.1 模式 4）。
- 方案：并入 anyul.history-search（v0.2.0）或独立小插件：
  - 触发：群内 @bot「总结一下/刚才聊了啥」；私聊「补看 <群名>」。
  - 实现：history_search（FTS5）拉时间窗内该群消息 → utils 池 llm.generate 话题分桶摘要；素材可复用 ov-memory 会话收拢产物（chat_summary），避免重复计算。
  - 回复策略两档可配：群内以「回复触发者消息」形式发（QQ 回复消息只通知触发者，天然低打扰）或私聊回。隔夜冷启动时主动给「昨晚摘要」可接 open-loop 提醒位。
- 依赖：已有（history-search、ov-memory、utils 池）。无新增外部依赖。
- 验收：群内问「刚才说什么了」→ 2 分钟内给出近 N 小时话题摘要；私聊可补看指定群指定时段；摘要不含敏感个人私事（过 prompt-guard 出站链）。

**P0-2 记忆显式指令（记住/忘掉）**
- 对标：Grok 口头设规（§3.1 模式 8）。
- 方案：ov-memory v0.4.0：
  - before_request Hook 加意图检测（正则粗筛 + fast_model 确认）：「记住X」「别忘X」「忘掉X」「我说的都是真的吗」。
  - 命中 → 写入独立类型 user_directed_fact（与自动抽取分库分表，带来源消息引用可追溯）；回执确认（拟人语气「记住了」）。
  - 管理面：dpanel 加 `dp 记忆` 面板（列表/删除/按群过滤），复用 dpanel 渲染。
- 依赖：ov-memory 写路径已稳定（v0.3.1 起会话收拢+抽取），纯增量。
- 验收：群内「记住我下周三搬家」→ 到期窗口内相关话题能召回且引用该事实；「忘掉X」删除成功有回执；WebUI 可审计全部 user_directed_fact。

**P0-3 回复形态宪法（出站硬约束层）**
- 对标：Grok 官方提示词宪法（grok-prompts 仓库公开可抄条目）。
- 方案：三层分离——表达学习继续管个性层，新增「宪法层」（PromptManager 自定义 prompt 段）：
  - 长度带：按群活跃度分档（安静群 ≤2 句，活跃碎嘴群允许 4-6 句）。
  - 禁项清单：markdown 头、列表符号、尾缀客套、说教短语黑名单（抄 Grok 清单再本土化）。
  - 语言跟随群消息主体语言。
  - 顺带修复已知出站质量 bug：`<thought>` 推理块泄漏（wo4 关思考配置的遗留问题）——在 send_service.after_build_message Hook 加出站清洗兜底剥离。
- 依赖：PromptManager 覆盖通路已有；出站清洗是新 Hook 用法但模式已被 prompt-guard 验证。
- 验收：抽样 100 条出站消息：无 markdown、无思考块、长度分布符合群档位；表达个性不受损（人工盲评）。

**P0-4 每群个性化配置（stream-profile）**
- 对标：ChatGPT 每群 custom instructions / Koishi 人格隔离 / 飞书 Aily 回复时机二选一。
- 方案：新插件 anyul.stream-profile（或并入 group-admin）：
  - KV 存 per-stream 配置：人设附加段、频控档（对齐 dynamic_gate 的 per-group 参数，把 1079703368 那次手动 sed 产品化）、语音边界、发图配额、摘要开关、回复时机档位（全量旁听=现状；仅@模式=新档，对齐官方平台产品化）。
  - 注入：maisaka.replyer.before_request 注入人设段；dynamic_gate 读档位。
  - 管理：WebUI 表单 + 群内管理员指令（走 prompt-guard admin_chat 授权通道）。
- 依赖：全部已有设施（KV、Hook、热重载、admin 通道）。
- 验收：A 群「安静高冷」B 群「碎嘴」配置后稳定复现；热重载秒生效；重启不丢（KV 持久）。

### P1（差异化能力，2-4 周量级，依赖外部资源）

**P1-1 生图社交能力**
- 对标：Meta AI imagine+remix（§3.1 模式 5）。
- 方案：新插件 anyul.image-gen：
  - 通道：new-api 现有网关探可用生图模型（先小流量质量验证再决定）。
  - Tool「生成图片」进 deferred 池（不进 toolgate 保底集，走 top_k 竞争）；拟人包装（不说「生成图片」，说「我来画一张」）。
  - 出站复用 pixiv 插件的图片下载/缓存/发送管线。
  - **安全**（MechaHitler 教训）：prompt 出站前过敏感词 gate（镜像用户语气的生图请求是高风险面）；每群每日配额（stream-profile 配置）+ 管理员白名单群。
  - Remix 玩法二期：「再来一张变体」「重画这条」引用互动。
- 依赖：new-api 生图通道质量（未验证，需先探测）；pixiv 管线复用。
- 验收：白名单群「画一张X」出图成功率 >90%；敏感 prompt 拒绝路径可用；单张成本记账。

**P1-2 定时与事件感知调度**
- 对标：钉钉感知触发 / nonebot apscheduler / 企微主动推送纪律。
- 方案：通用调度插件 anyul.scheduler：
  - 作息化主动发言：早安/话题发起/晚安，绑 stream-profile 的群级开关与时段；走 proactive.trigger，**静默会话被吞的坑→降级 ctx.send 直发 + 自建频控白名单**。
  - 群事件感知：进出群事件（napcat 事件订阅或 group-admin 联动）→ 欢迎语/欢送（拟人化，非公告腔）。
  - 与 task-loop 对接：任务到期提醒统一走 scheduler 主动通道；跨重启恢复参考 task-loop 重启补预算先例。
  - 与 open-loop 对接：提醒位复活统一收编。
- 依赖：napcat 事件面（需确认 adapter 暴露哪些群事件）；proactive 静默吞坑已知。
- 验收：重启后定时任务不丢不重复触发；静默群主动发言仅白名单生效；事件欢迎语在 30s 内到达。

**P1-3 按轮次深浅分档（成本优化）**
- 对标：Grok Auto/Fast/Expert/Heavy；Slack 分层套餐思想。
- 方案：replyer 侧复杂度路由：reply_likelihood 特征 + fast_model 判定「本轮是否需要工具链/深推理」→ 简单轮走 fast 池短上下文直出（跳 planner 深链），复杂轮走完整链。toolgate 的 L1 黄金探测已有分档观测基建，可直接做 A/B 统计。
- 依赖：现有任务池与观测基建，无新增。
- 验收：A/B：简单轮 token 消耗下降 ≥30%，抽检回复质量不掉档。

**P1-4 后台子代理插件化入口**
- 对标：Grok helper 外包（小主上下文+重活外包）。
- 方案：给 subagent_tasks 开 @API 编程入口（并发上限、超时、结论回投唤醒 planner），供 task-loop 执行轮（并行查证）与 web-search 聚合使用；严守事件循环规范（全异步）。
- 依赖：主程序代码改动（subagent_tasks.py 包装层），属主程序自行维护范围可直改。
- 验收：task-loop 执行轮可并行派 3 个子查询并汇总结论；超时与失败路径不阻塞主循环。

### P2 / 观察项

- **多 bot 群聊协作**：Grok Bot 的 2-6 bot handoff 是官方验证形态，但 bot 互发全计费、官方自己劝「少拉 bot」；wo4 有 dpanel 多宿主基础（mengyunqwq 式多 bot 人格隔离可参考）。等单 bot 价值吃满再评估。
- **内容安全分级**：QQ AI 输出违规封号不可解封（官方平台规则，个人号风控同向）；prompt-guard 管注入侧，输出侧敏感内容二次审（尤其配合生图）值得做，优先级随 P1-1 生图上线上浮。
- **语音对话化**：Grok Voice/通话形态；fish-audio 已有单向语音，「群内全双工/语音摘要」成本高、QQ 场景收益存疑，观察。

### 明确不跟进

1. **「AI 做东建群」独立空间模式**（ChatGPT 群聊/元宝派）：ChatGPT 已退役该形态，超出 MaiBot 作为 QQ 群成员的定位。
2. **侧边栏旁路助手模式**（Gemini/Gemini in Spaces）：QQ 无对应产品面。
3. **专门训练「插话社交判断」**：无训练资源；dynamic_gate 本土化路线继续迭代即可，吸收其「价值密度沉默」价值观到 reply_likelihood 特征即可。
4. **Guest Mode 式 @未入群 bot**：napcat 无对应机制。
5. **倒退为纯 @ 触发**：与拟人定位冲突，见 §3.2。

|---|---|---|
| 第一阶段 | P0-1 摘要补看、P0-2 记忆口令、P0-3 形态宪法、P0-4 stream-profile | 纯插件/配置层，零外部依赖，互相独立可并行 |
